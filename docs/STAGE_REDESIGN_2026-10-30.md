# 하나의 화면 안에서 이어지는 제품 이야기

## 입력 자료와 관찰

`C:\Users\samkj\Downloads\20261030-0549-06.6949687.mp4`는 **기존 사이트의 문제를 보여 주는 녹화**다. 목표 모션 레퍼런스로 취급하지 않았다. OpenCV로 1918×1078, 30fps, 약 48.77초임을 확인하고 타임스탬프별 프레임을 추출했다. 약 3초에는 첫 화면과 다음 내용이 함께 보이고, 약 27–30초에는 검토 설명과 다음 파란 영역이 함께 나타난다. 관찰할 수 있는 것은 화면의 스크롤 이동과 그 결과다. 녹화만으로 보이지 않는 상호작용을 추정하지 않았다.

방향은 새 요청에 명시된 원칙, 즉 **기본 브라우저 스크롤이 한 무대 안의 연속적인 변화를 구동하는 구성**이다. 기존 영상의 섹션 적층 구조를 유지하지 않았다. Apple의 브랜드나 자산은 사용하지 않았다.

## 구조

- `Experience.tsx`: 고정 헤더, 이야기, 설치, 참조, 결말을 조립한다.
- `story/Narrative.tsx`: 하나의 `820svh` 문서 범위 안에 `position:sticky; top:0; height:100dvh` 무대 하나를 둔다. 실제 스크롤 거리 약 720 뷰포트 %를 GSAP의 6.2 단위 타임라인에 매핑한다.
- `story/Narrative.module.css`: 모든 장면과 공통 그래픽을 같은 무대에 겹쳐 배치한다. 장면마다 별도 높이나 스냅 지점을 만들지 않는다.
- `content/story.ts`: 한국어·영어 장면 문구와 장 이동 지점을 관리한다.
- `story/OptionalDemo.tsx`: 이야기와 독립된 선택형 데모다. 참조 영역의 disclosure 안에만 있다.

휠 이벤트를 가로채지 않고, 스무스 스크롤 라이브러리나 타이머 재생을 사용하지 않는다. `scrub:true`로 스크롤 위치와 상태를 직접 연결한다. CSS sticky가 고정을 맡고 ScrollTrigger는 시간 진행을 맡는다. 따라서 pin spacer를 추가하지 않는다. 마지막 장이 끝난 뒤에만 무대가 풀리고 설치 영역으로 넘어간다.

폰트·이미지 로딩 후 refresh하고, 리사이즈 때 진행률을 보존한다. 효과와 이벤트는 해제한다. 모바일 주소창의 작은 높이 변화는 별도 분기로 다룬다. sticky + `overflow:clip` 조합에서 Chromium이 코드 글자를 간헐적으로 누락하는 현상을 캡처에서 발견했다. `overflow:hidden`과 공통 그래픽의 일관된 합성 레이어로 변경한 뒤 반복 캡처로 확인했다.

## 여섯 장면의 연결

1. **연결**: 화면 밖으로 크롭된 크롬·코발트 연결 이미지와 큰 제목. 이미지는 평면 자산이므로 확대·이동·소멸만 사용하며 물리적으로 휘거나 열리는 것처럼 만들지 않는다.
2. **근거**: 이미지가 빠지는 동안 같은 파란 연결선을 중심으로 소스와 인용 문서가 들어온다. `src/invoice.js → billing.md`를 읽는다.
3. **변경**: 배경이 파랑으로 변하고 코드에 `* i.qty`가 붙는다. 입력 `price 12 · qty 3`에서 결과는 36이지만 문서는 12에 머문다. `36 ≠ 12`와 상태 유지 설명을 함께 보여 준다.
4. **영향**: 같은 문서가 작은 근거 기록으로 정리되고 `shipping.md`가 추가된다. 변경 파일을 인용하는 `billing.md`만 강조한다. 다른 소스를 인용하는 shipping은 중립색이다. 재검토 신호와 참·거짓 판정을 구분한다.
5. **사람의 검토**: 두 패널이 다시 읽기 크기로 돌아온다. `drift --downgrade`로 검토 대기, 사람/에이전트의 문장 수정, `review --approve`, 승인 기록 순으로 이어진다. 날짜·이름은 실제 캡처 예시이며 신원 인증이라는 주장을 하지 않는다.
6. **다시 연결**: 같은 연결선이 굵은 닫힌 고리로 정리된다. 소스와 승인된 문서의 정체성을 유지한 채 설치 CTA로 끝난다.

정방향·역방향 모두 같은 타임라인을 사용한다. 중요한 장면 사이에는 읽을 수 있는 정지 구간을 두었다. 상시 부유, 튕김, 자동 회전은 없다.

## 정확성·접근성

제품 기준은 기존 증빙의 v1.42.0 / `7bb943f`다. 실제 명령과 출력은 `PRODUCT_CLAIMS.md`, `transcripts.ts`, `docs/evidence/`에서 유지한다. 소스 변경만으로 `verified`를 내리지 않는다. `drift`가 날짜 기반이며 같은 날의 변경을 놓칠 수 있다는 한계도 참조 영역에 둔다.

설치는 미리보기부터 시작하고 여덟 명령의 파일 쓰기 여부와 설치 필요 여부를 disclosure로 제공한다. 독립 데모는 세 파일×세 모드, 되돌리기, 파일 변경 시 명시적 초기화, 현재 결과 안내와 CLI 원문을 제공한다. 다음 행동은 lite이면 standard 전환, 영향 문서가 있으면 해당 이름과 CLI 안내, 인용 없는 파일이면 인용된 파일로 다시 시도로 달라진다.

모바일은 세로 소스–문서 관계로 재구성하고 740px 이하 높이에 별도 밀도를 적용한다. 장 표시, 건너뛰기, 키보드 이동과 focus를 제공한다. 비활성 장면은 `inert`/`aria-hidden`이다. `prefers-reduced-motion` 또는 읽기 전환은 긴 스크롤 무대를 제거하고 여섯 장면을 일반 문서로 제공한다. JavaScript 없이도 같은 설명과 설치 정보가 남는다.
